# One shipped ML2 workload, from a camera frame to hand-tracking data

**STRONG EVIDENCE.** Magic Leap 2 ships a C5 job that takes world-camera data and trained weights, AArch64 code that consumes its detection output, and an Android x86 library that reads the resulting hand-tracking data type. The public API retrieves tracking state. The binaries give no reason to equate one API call with one camera frame, C5 launch, PCI transaction or interrupt. This is a static reconstruction of OS 1.12.1 (build 9601). A per-frame runtime trace was unavailable.

The follow-up verified the vendor archive SHA-256 `9747b3652e20746596b64b0b244bd23a047ba47d4eb3d392271cac08a615f28c`, the Android system image and the CVIP RO image against the existing inventory, then extracted the ELFs read-only. All instruction addresses below are ELF virtual addresses. The C5/Q6 addresses are DSP job-map values. File offsets are explicitly identified. [Vendor image and hashes](../evidence/artifacts.md) · [Host ELF index](../evidence/host-index.tsv) · [ARM/DSP index](../evidence/cvip-side.tsv)

## Reproduce the new edges offline

The host pair has SHA-256 `fed3a752b96b98080357f6f20aaeeadba108565bf4971f9343f683dab614a542` (public API) and `32869a49acf1d61ffa4a5582ab58815b57ba95b3253c721af6be8ba0d8bfd5ef` (hand-tracking component). The ARM blocks library hashes to `2f13ed42c3af5dc68d0f20dd96ac52b6c22a2697f68da05894bad94b1dd77756`. Use these commands in the directory containing each extracted ELF. The existing reproduction guide describes read-only image extraction. [Extraction guide](../reports/reproduction.md)

```sh
llvm-readelf -rW libml_perception_hand_tracking.so | rg '00000000000292a8' | c++filt
llvm-objdump -d --start-address=0x19f03 --stop-address=0x19f31 libml_perception_hand_tracking.so
llvm-objdump -d --start-address=0x19504 --stop-address=0x195ac libhand_tracking_blocks-cvip-arm-hw.so
llvm-objdump -d --start-address=0x4c450 --stop-address=0x4caa4 libcv_engine-cvip-arm-hw.so | rg 'DequeueThreadJob|ExecuteJob|NotifyWorkloadComplete'
```

**What is reusable.** On supported Mero hardware, the typed job maps, fixed-length resource checks, input/output ownership and host result type give an independent reader concrete interoperability checks. The PCI/PL320 bootstrap, IOMMU address domains, trusted boot assets, camera calibration and compiled C5/Q6 programs are platform-specific. The remaining decisive evidence would be a known-good trace linking one frame ID, buffer and completion across those boundaries. Neither that trace nor a general model compiler or a compatible Deck endpoint was available.
